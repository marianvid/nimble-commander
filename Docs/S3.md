# Amazon S3 and S3-compatible storages

This fork adds a native S3 virtual file system to Nimble Commander. An S3 bucket is browsed and manipulated in a file
panel exactly like a local folder, an SFTP server or a WebDAV share - no mounting, no FUSE, no rclone, no AWS CLI.

## Connecting

`Go → Connect To → S3 Storage...`, or `⌘K` (Manage Connections) → `+` → `S3 Storage...`.

| Field | Meaning |
|---|---|
| Title | Free-form label shown in the connections list. |
| Service | `Amazon S3` or `S3-compatible` (MinIO, Cloudflare R2, Wasabi, Backblaze B2, Hetzner, ...). |
| Endpoint | Only for S3-compatible services, e.g. `https://minio.example.com:9000`. Leave empty for AWS. |
| Region | E.g. `eu-central-1`. Optional on AWS: buckets living in other regions are detected automatically. Use `auto` for Cloudflare R2. |
| Bucket | Optional. Empty shows the list of all buckets; a name roots the connection at that bucket (useful when the credentials are not allowed to list buckets). |
| Credentials | Either keys typed into the dialog, or a profile from the AWS CLI files (`~/.aws/credentials`, `~/.aws/config`). |
| Access Key ID / Secret Access Key | Manual keys. The secret key is stored in the macOS Keychain, never in the settings file. |
| Use path-style addressing | `https://host/bucket/key` instead of `https://bucket.host/key`. Needed by MinIO and most self-hosted services. |

### AWS CLI profiles

When a profile is selected, nothing secret is stored by Nimble Commander: the access key, secret key, session token,
region and `endpoint_url` are re-read from `~/.aws` on every connect, so rotated keys are picked up automatically.
`AWS_SHARED_CREDENTIALS_FILE` and `AWS_CONFIG_FILE` are honored. Region and endpoint typed into the dialog take
precedence over the profile's values.

## What works

- Listing buckets and "directories" (key prefixes, `/` delimiter), with pagination for any number of objects.
- Reading: random access through ranged GETs with an 8 MiB read-ahead window, so the internal viewer and copying are
  efficient even for huge objects.
- Writing: objects up to 16 MiB are uploaded with a single PUT; larger ones use multipart uploads with bounded memory
  (one part in memory at a time, part size grows automatically to stay below the 10,000 parts limit). Interrupted
  uploads are aborted, so no orphaned parts are left behind.
- Creating and removing directories (as zero-byte `name/` marker objects), creating and deleting buckets.
- Rename/move of files and whole directories via server-side copy + delete (multipart copy for objects over 5 GiB).
- Copying between S3 and any other VFS: local disk, SFTP, FTP, WebDAV, archives, another bucket.
- Keys with spaces, `+`, parentheses, non-ASCII characters, `./` and `../` segments.
- Session tokens (temporary STS credentials), dotted bucket names over TLS, automatic per-bucket region discovery.

## Limitations inherent to S3

- Directories don't really exist, they are key prefixes. An "empty directory" is a zero-byte object named `prefix/`.
- Renaming a directory touches every object under it - it's an O(n) operation, not an atomic one.
- No permissions, owners or settable timestamps; the shown date is the time of the last upload.
- There is no trash: deletions are final unless the bucket has versioning enabled.
- Directory listings are cached for 30 seconds; `⌘R` forces a refresh.

## Implementation

The code lives in `Source/VFS/source/NetS3`, split into layers with dependencies pointing downwards only:

| Layer | Files | Responsibility |
|---|---|---|
| VFS adapter | `S3Host`, `File`, `Cache` | Implements `nc::vfs::Host` / `VFSFile`; maps panel operations onto S3 calls; listing cache and change notifications. |
| S3 API | `Client` | Typed facade over the S3 REST operations; error mapping; region auto-discovery and retry. |
| Protocol | `SigV4`, `Addressing`, `Xml`, `PathMapper` | AWS Signature V4, virtual-hosted vs path-style URLs, XML parsing, VFS path ↔ bucket/key mapping. Pure functions, no I/O. |
| Transport | `Http` (interface + pool), `CurlHttpClient` | Blocking HTTP over libcurl with keep-alive connection pooling. The client depends only on the `HttpClient` interface. |
| Utilities | `Crypto`, `Encoding`, `AwsProfiles`, `Configuration` | SHA-256/HMAC via CommonCrypto, URI encoding, AWS CLI profile parsing, the host configuration. |

The UI side is `S3ConnectionSheetController` (built in code, no NIB) plus the `S3` connection type in
`NetworkConnectionsManager`, persisted by `ConfigBackedNetworkConnectionsManager`.

### Tests

`Source/VFS/tests/NetS3/S3_UT.cpp` (part of `VFSUT`):

- SigV4 is checked against the signatures published in the AWS documentation.
- XML parsing, URL addressing, path mapping, part sizing and AWS profile parsing have dedicated unit tests.
- An in-memory fake S3 server (which also re-verifies every request signature) exercises the whole host end to end:
  listings and pagination, small/zero-byte/multipart uploads, ranged reads, directories, renames, special characters,
  open-for-write semantics and authentication failures.
- An integration test runs against a real server when these variables are set, e.g. with a local MinIO:

```
NC_S3_IT_ENDPOINT=http://127.0.0.1:9010 NC_S3_IT_ACCESS_KEY=... NC_S3_IT_SECRET_KEY=... ./VFSUT "nc::vfs::s3*"
```
